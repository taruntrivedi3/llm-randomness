# LLM randomness experiments

Requested outputs: two separate notebooks, each with 2,000 samples targeting mean 10 and standard deviation 2. All random input must come from fresh model calls. No locally generated random numbers, shuffled grouping, output recentering, or shared conversation history.

Backend: configured LiteLLM OpenAI-compatible chat completions endpoint. Model `gpt-4.1-mini`; temperature 1, top_p 1, max_tokens 32, n 1, no seed, no tools, no system prompt. Record returned model and fingerprint. HTTP retries are logged individually. Malformed outputs remain in raw data; whole production groups containing malformed outputs are excluded and replaced by fresh groups. Calls are assigned immutable group and position indices before dispatch. Completion order never determines grouping.

Binary experiment: eight prespecified literal-sign pilot candidates, 100 calls each. All yielded p>=0.99, so retained them and expanded the exploratory pilot with eight binary-label prompts before calibration. Select the eligible prompt with minimum absolute deviation from 0.5 (eligibility: all pilot answers valid; ties broken by candidate index). Fixed, disclosed token-to-sign mappings contain no additional randomness. Collect 1,000 fresh calibration calls, then 2,000 valid groups of 40 fresh flips. Calibration and production are disjoint. Freeze p_hat from calibration and transform X=10+2*(sum(Y)-40*(2*p_hat-1))/sqrt(40*4*p_hat*(1-p_hat)). Do not center or scale using production data. Report calibration uncertainty and exact transformed-binomial discreteness.

Ordering experiment: identical integer prompt, independent calls in groups of 10. Pilot 100 groups to measure ties and invalids, then fresh production groups. Discard entire tied or invalid groups without tie breaking; preserve all responses. For accepted groups rank the ordering lexicographically via Lehmer code, K in 0..10!-1. U=(K+0.5)/10!, X=10+2*Phi^-1(U). Stop after 2,000 accepted groups in planned group-index order, not completion order. Do not reuse the pilot for production.

Audit data interface: `data/manifest.json`, `data/responses.jsonl`, and `data/attempts.jsonl`. Terminal response records contain request_id (local stable string), phase, prompt_id, prompt, group_id (integer or null), position (integer), raw_response, value (integer or null), valid (boolean), status, provider_response_id, model, system_fingerprint, started_at_utc, finished_at_utc, elapsed_seconds, usage. Phases are `binary_pilot`, `calibration`, `clt`, `integer_pilot`, `permutation`. Manifest contains prompts, settings, selection, calibration and phase status/counts. Every terminal request has one response record; attempts preserve HTTP retries and errors. CSV derivatives should retain raw request IDs.

Resume hardening: requests_started.jsonl journals dispatch before the network await (added after the exploratory pilot). Original successful/invalid replies are recovered from attempts.jsonl if a crash happens before terminal-response append. Changed settings, endpoint, existing prompt text, response mappings, or request grouping are rejected on resume. Initial benchmark calls are not experiment input. Fresh API calls intentionally omit Codex agent system/developer instructions.

Notebooks are offline analyses, not live collection launchers. They must execute against partial or complete snapshots, distinguish missing data from zero results, and validate hashes when completion manifest provides them. Desired files: `../llm_clt_normal_2000.ipynb` and `../llm_permutation_normal_2000.ipynb`.
